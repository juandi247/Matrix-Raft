Overview

Raft
A consensus algorithm that lets a group of nodes agree on a shared log, even when some nodes crash or messages are delayed. Simba implements it from scratch.
Deterministic simulation testing
The whole system runs inside a simulation where the clock, the network and the failures are all controlled. The same run always gives the same result, so any failure can be replayed exactly.
Matrix mode
The deterministic simulation. The engine controls time, message delivery and crashes.
Real mode
The same Raft with real timeouts, persistent storage and messages sent over the network. Only the interfaces change.

Raft in short

Leader election

Every node is a follower, a candidate or the leader. A follower that stops hearing from the leader becomes a candidate and asks the others for votes. If it gets a majority, it becomes the leader.

Each election starts a new term. A node that sees a higher term steps down.

Log replication

Commands go to the leader, which appends them to its log and sends them to the followers. An entry is committed once a majority of nodes has stored it.

Committed entries never change, and every node applies them in the same order.

How Simba runs Raft

One Raft, two modes

Raft never touches time, storage or the network directly. It talks to three interfaces. Matrix mode plugs in simulated versions, and Real mode plugs in the real ones.

Matrix mode, step by step

  1. Time is a counter.The engine is a loop that advances time in ticks: plain, monotonic integers.
  2. Messages are fire and forget.Nodes never call each other. Every message goes into the event log.
  3. Every event has a delivery tick.Each entry stores its type, sender, receiver and the tick when it arrives. A later tick simulates network latency.
  4. Nodes reply in the future.When the tick arrives, the node handles the message and schedules its reply at a future tick.
  5. Failures are events too.Crashes and restarts go through the same log, so they replay like everything else.
